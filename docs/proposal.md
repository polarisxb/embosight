## 一、项目愿景

EmboSight 致力于构建**首个面向视觉障碍人群的零样本具身智能辅助系统**。

前沿人工智能技术不应只服务已经掌握工具的人群，更应为那些在物理世界中面临结构性困境的特殊群体——尤其是视觉障碍人士——提供真正具有感知与执行能力的智能伙伴。

通过将主动感知（Active Perception）、多模态大模型（VLM/LLM）与零样本任务泛化（Zero-Shot Generalization）三者深度融合，EmboSight 旨在让视障者通过自然语言获得"看得懂世界、听得懂指令、帮得上忙"的真正具身助手。

**愿景一句话**：让 1731 万视障人士拥有一双能听懂他们的"机器之眼"。

## 二、问题陈述与研究空白

### 2.1 现实困境（A 项可行性证据链）

| 数据维度 | 数值 | 来源 |
|---|---|---|
| 中国视障人士总数 | 1731 万 | 中国残联《2023 年残疾人事业发展统计公报》 |
| 全国导盲犬总数 | < 200 只 | 中国导盲犬大连培训基地公开数据 |
| 单只导盲犬培训成本 | 12-15 万元 | 同上 |
| 导盲犬覆盖率 | < 0.001% | 估算（200/1731 万） |
| 我国 60 岁以上老年人 | 2.97 亿 | 民政部 2024 年统计公报 |
| 独居/空巢老人 | 约 1.2 亿 | 国家卫健委 2023 年估计 |
| 全球残障人口 | 约 13 亿 | WHO 2022 年报告 |

视障人士每日高频需求集中于：
- **找物**：药品、眼镜、钥匙、手机、餐具等（每日 20-50 次）
- **环境感知**：陌生环境的物品位置、布局、危险点
- **操作辅助**：厨房使用、衣物分类、文件阅读
- **安全识别**：热源、锐器、易碎物、过期食品

### 2.2 现有方案不足

| 方案类型 | 代表产品 | 局限 |
|---|---|---|
| 物理辅助 | 盲杖、导盲犬 | 仅避障/导航，无法识别物品或动手帮助 |
| 数字辅助 | 屏幕阅读器（NVDA、JAWS） | 只解决数字鸿沟，对物理世界无能为力 |
| 视觉描述 | Be My Eyes、SeeingAI | 单图被动描述，无主动感知能力 |
| 商用 AI | OrCam MyEye | 仅识别文字与人脸，无操作能力，售价过万元 |
| 智能音箱 | 天猫精灵、Alexa | 听得懂指令，没有"手"也没有"眼" |

**关键缺口**：现有方案中**没有任何产品同时具备**——
1. 听懂自然语言
2. 主动观察环境
3. 提供视障专用描述
4. 物理执行（指引/取物）

| 学术领域 | 当前研究状态 | 视障辅助场景空白 |

**研究空白汇总**：具身智能 × 视障辅助 × 零样本泛化的**三元交叉**领域，国内外公开文献中未见报道。

## 三、解决方案总览

EmboSight 是一个**零样本视障具身辅助智能体**，由三大模块构成完整的"感知-决策-动作"闭环：

```
视障者输入 (自然语言)
        │
        ▼
┌────────────────────────────────────────┐
│  ① 零样本视障任务分解器                │
│     LLM + Few-shot Blind Templates     │
└────────────────────────────────────────┘
        │ 子任务序列
        ▼
┌────────────────────────────────────────┐
│  ② 零样本主动视角规划器（王牌）         │
│     LLM-driven Next-Best-View          │
└────────────────────────────────────────┘
        │ 视角序列
        ▼
┌────────────────────────────────────────┐
│  机械臂执行 + 多视角图像采集           │
│     Franka Panda @ RoboCasa            │
└────────────────────────────────────────┘
        │ RGB-D 多视角观察
        ▼
┌────────────────────────────────────────┐
│  ③ 零样本视障友好描述器                │
│     VLM + Blind-Aware Prompt           │
└────────────────────────────────────────┘
        │ 结构化描述
        ▼
TTS 语音输出 / 物理指引
        │
        ▼
视障者接收
```

## 五、系统架构

### 5.1 模块划分

```
src/
├── task_decomposer.py        创新点 ① 零样本视障任务分解
├── active_planner.py         创新点 ② 零样本主动视角规划
├── scene_describer.py        创新点 ③ 零样本视障友好描述
├── pipeline.py               主控流程
├── env_wrapper.py            RoboCasa 仿真接入
├── camera_controller.py      机械臂运动学 + 摄像头控制
├── vlm_backend.py            Qwen2.5-VL 推理封装
├── llm_backend.py            DeepSeek API 调用封装
├── eval.py                   零样本评估脚本
└── viz.py                    可视化与视频生成
```

### 5.2 数据流

```
[输入] 视障者自然语言查询
       │
       ▼
[任务分解器] LLM(query, blind_templates) → subtasks: List[SubTask]
       │
       ▼
[主动视角规划器] LLM(subtasks, observations, viewpoint_lib) → next_vp
       │  循环：直到所有 subtask 被覆盖或达到最大视角数
       ▼
[机械臂执行] env.move_arm(next_vp) → image[i]
       │
       ▼
[视障描述器] VLM(image[i], blind_prompt) → desc[i]: StructuredDesc
       │
       ▼
[聚合输出] aggregate(desc[1..n]) → final_response: BlindFriendlyText
       │
       ▼
[TTS / 物理指引] speak(final_response); env.point_at(target)
```

### 5.3 关键数据结构

```python
@dataclass
class SubTask:
    type: Literal["identify", "locate", "describe", "alert", "guide"]
    target: str
    priority: int
    coverage_status: bool

@dataclass
class Viewpoint:
    name: str   # 例 "top_view", "left_close"
    pose: tuple[float, ...]   # (x, y, z, roll, pitch, yaw)
    purpose: str   # 该视角要达成的子任务

@dataclass
class StructuredDesc:
    objects: list[str]
    positions: list[dict]  # {obj, direction, distance_cm, height_cm}
    safety_alerts: list[str]
    actionable_advice: list[str]
```

## 六、三大创新点详述

### 6.1 创新点 ①：零样本视障任务分解

**问题**：通用 LLM 任务分解忽视视障者关键需求维度（方位、距离、触觉、安全），且视障专属训练数据稀缺，必须采用零样本方法。

**方法**：
- 构建**视障专属任务模板库**（10 大类，覆盖找物 / 描述 / 取物 / 导引 / 警示 / 阅读 / 烹饪 / 着装 / 用药 / 社交，共 50+ 子任务原型）
- 设计 **Few-shot Prompt 框架**：每次推理时检索最相似的 K=3 个模板示例作为上下文
- 强制结构化输出：[type, target, priority, blind_dimension]

**关键创新**：
- **首次提出视障专属任务分解模板库**——可作为后续相关研究的基础数据集
- **视障关键维度强制编码**——通用 LLM 不会主动加，我们模板里写死
- **零训练即用**——纯 Prompt 工程实现

**评估**：
- 指标：零样本任务分解准确率（Unseen 查询下生成正确子任务序列的比例）
- 预期：[实测填入] vs Baseline [实测填入]

### 6.2 创新点 ②：零样本主动视角规划（王牌）

**问题**：单视角 VLM 信息不全，经典 Next-Best-View（NBV）依赖几何先验，不适配语言驱动的视障辅助场景。

**方法**：
- **离散视角库设计**：12 个标准视角（顶 / 左 / 右 / 前 / 后 × 远 / 近 × 倾斜组合），每个视角参数化为 (位置, 朝向)
- **LLM-NBV 决策算法**：将"下一最优视角"问题转化为 LLM 选择题，输入当前观察 + 子任务，输出最优视角索引
- **早停机制**：当 LLM 判断"信息已足以回答查询"时主动终止，平均扫描视角数 vs 全扫描

**关键创新**：
- **首次将大语言模型引入视障辅助 Active Perception**——填补 LLM-driven NBV × 视障辅助交叉空白
- **离散视角库降低工程复杂度**——回避连续动作空间训练难题
- **任务驱动而非几何驱动**——视角选择基于"任务覆盖度"而非"几何信息熵"

**评估**：
- 指标：零样本视角规划成功率（Unseen 场景下完成任务覆盖的比例）
- 预期：[实测填入] vs Baseline [实测填入]

### 6.3 创新点 ③：零样本视障友好场景描述

**问题**：通用 VLM 输出（如"桌上有水杯"）对视障者不可用，缺方位、缺距离、缺安全提示、缺行动建议。

**方法**：
- **视障专属 Prompt 模板**：五维度强制输出
  - ① 物体识别（名称 + 形状特征）
  - ② 方位距离（前/后/左/右 + cm 级距离）
  - ③ 触觉特征（材质 + 温度 + 形状）
  - ④ 安全提示（热/冷/锋利/易碎/不稳定）
  - ⑤ 行动建议（怎么取 / 怎么避）
- **几何后处理**：利用仿真器深度图反推真实距离，将 VLM 文字描述与几何数据对齐，输出厘米级精度
- **视障友好词汇库**：触觉描述（圆筒形、长方体）替代单纯颜色描述；温度提示（温热、常温、凉）；危险等级（高、中、低）

**关键创新**：
- **首次系统化将 Accessibility 设计学引入 VLM 输出改造**
- **跨学科融合**：无障碍设计 + 多模态大模型 + 具身 AI
- **可量化的视障友好度指标**：建立 5 维度加权评分体系

**评估**：
- 指标：物体识别准确率、距离精度（cm）、视障友好度评分（5 维度）
- 预期：[实测填入] vs Baseline [实测填入]

### 10.1 评估指标设计

| 指标类别 | 具体指标 | 单位 | 测量方式 |
|---|---|---|---|

| 视角规划 | 平均扫描视角数 | 次 | 早停机制效率 |
| 视障描述 | 物体识别 F1 | - | Precision-Recall |
| 视障描述 | 距离绝对误差 | cm | 与 ground-truth 对比 |
| 视障描述 | 视障友好度 | 0-10 | 5 维度加权评分 |
| 端到端 | 任务成功率 | % | 完整 pipeline 评估 |

### 10.2 实验设计

```
任务划分:
  Seen 任务（训练集）：5 个视障查询场景
    - "找药瓶"
    - "描述桌面"
    - "递水杯"
    - "看冰箱里有什么"
    - "判断台面是否安全"

  Unseen 任务（零样本测试集）：10 个全新场景
    - "把那个有点凉的东西挪到我手边"
    - "我怀疑桌上那个东西过期了"
    - "中间不要有挡道的"
    - …（具体场景在仿真中实现）

Baseline 对比:
  B1. 固定视角扫描 + 通用 VLM
  B2. 随机视角扫描 + 通用 VLM
  B3. 本文方法（消融：去掉创新①）
  B4. 本文方法（消融：去掉创新②）
  B5. 本文方法（完整版）
```

### 10.3 视障友好度 5 维度评分体系（自创指标）

| 维度 | 权重 | 评分细则 |
|---|---|---|
| 物体识别完整性 | 0.25 | 关键物体识别召回率 |
| 方位距离精度 | 0.25 | 距离误差 ≤ 5cm 得满分 |
| 触觉特征覆盖 | 0.20 | 包含形状/材质描述比例 |
| 安全提示准确率 | 0.20 | 危险物体提示正确率 |
| 行动建议可行性 | 0.10 | 建议是否可执行（人工审核） |

总分 = ∑（维度得分 × 权重），区间 0-10。
